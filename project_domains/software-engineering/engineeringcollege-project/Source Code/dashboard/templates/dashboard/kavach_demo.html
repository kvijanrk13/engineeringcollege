Internal System Design

  1. Sender opens /projects/kavach/ and signs in with Gmail.
  2. Sender selects the receiver Gmail account and uploads a file.
  3. The server generates a random AES key and random nonce/IV.
  4. The server hashes the original file with SHA-256 and signs that hash with the sender private key.
  5. The server encrypts the AES key for the selected receiver public key.
  6. The server encrypts the file with AES-GCM and stores only the encrypted .aesgcm file.
  7. The page creates a transfer ID and access code for the receiver workflow.
  8. Receiver opens Shared With Me, selects the file, passes permission, expiry, and revocation checks, decrypts the AES key with the receiver private key, decrypts the file, and KAVACH verifies hash and sender signature before download.

Requirement Rules

  • Sender and receiver use only /projects/kavach/.
  • Sender and receiver must use verified Gmail sign-in.
  • Sender selects the receiver Gmail account before encryption.
  • Images, PDFs, Word, Excel, PowerPoint, audio, video, ZIP, and unknown file formats are encrypted as bytes and restored exactly during download.
  • Owner can revoke receiver access at any time; revoked records cannot be downloaded or decrypted through the system.
  • Receivers download from Shared With Me after access permission, expiry, and revoked-status checks.
  • AES keys for new transfers are encrypted for the receiver key pair before storage.
  • Each upload stores a SHA-256 hash, uploader public key, and digital signature.
  • Original uploaded files are not stored.
  • Encrypted storage and decrypted download both work on localhost and Render through the same route.
