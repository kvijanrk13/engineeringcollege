Book Bank / Library Management System - Documentation

1. Development of Problem Statements

A Library Management System (LMS) is a project that manages and stores book information electronically according to user needs. The system helps students, faculty and the librarian to keep a constant track of all the books available in the library. It allows both the admin and the member to search for the desired book. It becomes necessary for educational institutes like colleges to keep a continuous check on the books issued and returned and even calculate fines.

Existing System: The existing system is physical maintenance of the library in which all transactions are done manually. This method takes more time for borrowing or returning a book and for searching members and books. Preparing lists of borrowed books and available books takes more time. It takes several days to verify all records in larger libraries.

Proposed System: The proposed system is a Book Bank / Library Management System. All difficulties in manual management have been rectified by implementing a computerized system. The administrator (librarian) can add members, add books, search members, search books, update information, edit information, borrow and return books quickly. The proposed system provides better and efficient service to members, reduces workload, allows faster retrieval of information, provides proper monitoring, reduces paperwork, provides data security, and makes all details available with a single click.

2. Preparation of Software Requirement Specification Document, Design Documents and Testing Phase Documents

Software Requirements Specification (SRS): The purpose of this document is to record the requirements of an application that will automate the whole procedure of a library. The system is web-based. For Members: search books based on Title, Author, Subject, Keyword; issue/return books; renewal of books. For Library Staff: automatic installation; simple and intuitive GUI; shortcut keys and point-and-click operation; security features like access control using passwords and login-id; automatic calculation of late fee; facility to add/delete members, library staff and books.

Software Design Document (SDD): The Library Management System is divided into two modules - Student and Admin. Admin can add/update/delete members, add/update/delete books, issue new books to students, search students by student ID, view student details, and change own password. Students can register and get a student-id, view their dashboard, view listed books, update their profile, view issued books and return date-time, and change or recover their password.

Test Plan: The test plan covers Librarian Interface (Master Data, User Management, Reports), Student Interface (Profile, Search, Reserve), and Faculty Interface (Profile, Search, Reserve, Request Order). Features to be tested include adding new categories/books, editing categories/books, managing transactions, creating/editing members, generating reports, login, viewing issue details, searching books, and reserving books.

CASE tools are used by software project managers, analysts and engineers to develop software systems. There are a number of CASE tools available to simplify various stages of the Software Development Life Cycle such as Analysis tools, Design tools, Project management tools, Database Management tools, and Documentation tools.

5. Performing the Design by Using Design Phase CASE Tools

The design of the Book Bank - Library Management System was performed using StarUML with the following modeling approaches: 4+1 View Model, Default Approach, Rational Approach, UML Components Approach, and Empty Approach.

Design Structural Models - Book Bank LMS:

  • Class Diagram: Shows the static structure of the system with classes like Book, Author, Student, Issue, Fine, and their relationships.
  • Object Diagram: Represents instances of classes and their relationships at a particular moment.

Design Behavioral Models - Book Bank LMS:

  • Use Case Diagram: Represents the functionality of the system from the user's perspective, showing actors (Student, Librarian, Faculty) and their interactions with the system.
  • Sequence Diagram: Shows object interactions arranged in time sequence, particularly for book issue and return processes.
  • Collaboration Diagram: Shows the structural organization of objects that send and receive messages.
  • Statechart Diagram: Represents the states of a book (Available, Issued, Returned, Overdue) and transitions between them.
  • Activity Diagram: Represents the workflow of book issue and return processes.

Design Architectural Models - Book Bank LMS: Component Diagram shows the organization and dependencies among components (Book Management, User Management, Issue Management, Fine Management). Deployment Diagram shows the physical deployment of artifacts on nodes (Web Server, Database Server, Client Browsers).
