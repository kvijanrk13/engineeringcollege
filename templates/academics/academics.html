Computer Registers

Start: 00:14Topic verifiedCOA
Watch source at 00:14 ↗

A register is a small, high-speed storage unit inside the processor. It is formed from a group of flip-flops, with each flip-flop storing one binary bit. A 16-bit register therefore contains 16 flip-flops. Registers temporarily hold instructions, addresses, input data, intermediate values, and results while the CPU performs operations.

Registers used in the basic computer

RegisterSizePurpose
AR — Address Register12 bitsHolds the memory address selected for a read or write operation.
PC — Program Counter12 bitsHolds the address of the next instruction. It normally increments after an instruction is fetched.
DR — Data Register16 bitsHolds data read from memory or data that is to be written to memory.
AC — Accumulator16 bitsMain arithmetic and logic register; receives operands and stores ALU results.
IR — Instruction Register16 bitsHolds the current instruction while its operation code and address field are decoded.
TR — Temporary Register16 bitsStores intermediate data needed briefly during processing.
INPR — Input Register8 bitsReceives an 8-bit character or data byte from an input device.
OUTR — Output Register8 bitsHolds an 8-bit character or data byte before it is sent to an output device.

How register operations are controlled

Control inputs determine what happens on a clock transition. Load (LD) transfers a new binary value into the register, increment (INR) adds one to its present value, and clear (CLR) resets it to zero. If none of these controls is active, the register keeps its current value. Not every register requires every control input; its available operations depend on its role in the CPU.

Key idea: registers are the CPU’s immediate working storage. Their names describe the particular information they hold, while control signals decide when that information is loaded, changed, or cleared.

Common Bus System for Computer Registers

Start: 12:35Topic verifiedRegister transfer
Watch source at 12:35 ↗

A bus is a shared group of wires used to transfer binary information between registers. Giving every register a separate connection to every other register would require too many wires. A common bus provides one shared transfer path, making the hardware simpler and allowing the control unit to select one source register at a time.

How the common bus is formed

  1. The outputs of the registers are connected to multiplexers. For a 16-bit system, one multiplexer is used for each bus bit, so the bus contains 16 parallel lines.
  2. The three selection signals S2, S1, and S0 are applied to every multiplexer. Together they choose which register places its value on the bus.
  3. The selected source appears on the common bus. The control unit then activates the load input of a destination register.
  4. At the active clock edge, the destination copies the bus value. Only one source may drive the bus at a time, although the value can be delivered to one or more enabled destinations.

The exact selection table follows the inputs connected to the multiplexers. In the basic-computer arrangement, a code selects AR, PC, DR, AC, IR, TR, memory data, or a zero value. Because AR and PC are 12-bit registers, their four unused high-order bus positions are filled with zeros. Likewise, an 8-bit input register uses only the low-order bus lines.

Register-transfer example

To perform AR ← PC, the control unit selects PC as the bus source and enables LD(AR). On the next clock edge, AR receives the 12 low-order bits carried by the bus. For a memory read such as DR ← M[AR], AR supplies the address, a read control accesses memory, and the returned 16-bit word is loaded into DR.

Important distinction

The three bus select lines choose the source. A register’s load input chooses the destination. Increment and clear controls can change a register without selecting a value from the bus. These signals are generated by the control unit from the decoded instruction and timing sequence.

Complete transfer: select a source with S2S1S0 → place its bits on the common bus → enable the destination register’s load input → apply the clock edge → the destination stores the transferred value.

Instruction Cycle

Start: 08:37Cleaned from narrationCOA
Watch source at 08:37 ↗

An instruction cycle is the complete sequence of operations performed by the CPU for one instruction. The processor fetches an instruction from memory, decodes it to identify the required operation, determines whether an additional memory access is needed, executes the operation, and then checks for an interrupt. This sequence repeats until every instruction in the program has been completed.

Why it is called a cycle: after one instruction is completed, the sequence counter returns the control unit to timing signal T0. The CPU then performs the same fetch-and-decode sequence for the next instruction. Only the execution steps change according to the decoded operation.

Instruction format used in the basic computer

The lecture explains the instruction cycle using a 16-bit basic computer. Each instruction is divided into three fields:

Bit 15
Indirect bit I
Bits 14-12
3-bit opcode
Bits 11-0
12-bit address or function field
  • The I bit selects direct or indirect addressing for a memory-reference instruction.
  • The opcode tells the control unit which operation must be performed. Its eight possible decoded outputs are named D0 through D7.
  • The 12 low-order bits hold a memory address when D7 = 0. When D7 = 1, they specify a register-reference or input/output function.

Registers and control elements involved

ElementRole in the instruction cycle
PC — Program CounterContains the address of the next instruction and increments after the current instruction is fetched.
AR — Address RegisterReceives the instruction address, the instruction's address field, or an indirect effective address.
IR — Instruction RegisterHolds the complete 16-bit instruction while its opcode, I bit, and remaining fields are decoded.
DR — Data RegisterTemporarily holds an operand read from memory for operations such as AND, ADD, and ISZ.
AC — AccumulatorHolds an arithmetic or logic operand and receives the result produced by the ALU.
SC — Sequence CounterGenerates the ordered timing steps. Clearing SC after execution makes the next timing signal T0.
I and RI records the addressing-mode bit; R records whether an interrupt cycle is required.

Instruction-cycle phases

  1. Fetch: read the next instruction from memory into the Instruction Register (IR).
  2. Decode: decode the operation code and separate the instruction fields.
  3. Determine the effective address: for a memory-reference instruction, decide whether the address is direct or indirect and obtain the effective address when necessary.
  4. Execute: perform the register-reference, memory-reference, or input/output operation specified by the instruction.
  5. Interrupt: if interrupts are enabled and a request is pending, save the return address and transfer control to the interrupt service routine.

Fetch and decode timing

The sequence counter (SC) produces timing signals T0, T1, T2, .... Each timing signal enables the microoperations required during one clock interval. The fetch and decode operations are common to every instruction:

T0: AR ← PC
T1: IR ← M[AR], PC ← PC + 1
T2: D0...D7 ← Decode IR(12-14), AR ← IR(0-11), I ← IR(15)

At T0, the address of the next instruction moves from PC to AR. At T1, memory is read, the instruction enters IR, and PC increments so that it points to the following instruction. At T2, the opcode is decoded by a 3-to-8 decoder, the 12-bit address field is copied to AR, and the most significant bit is copied to the indirect-address bit I.

Meaning of each connection

  • AR to memory Address: the contents of AR continuously identify the memory location to be accessed.
  • Memory to bus input 7: when Read is active, the selected memory word becomes a possible bus source.
  • PC to bus input 2: selecting source 2 places the next-instruction address on the bus.
  • Bus to AR and IR: the common bus reaches register inputs, but a register changes only when its load signal is asserted.
  • PC increment input: PC can increment internally at the same clock edge at which IR receives the fetched instruction.
  • Clock: control signals prepare the paths during the timing interval; the active clock edge stores the new register values.
  • OR gates: several control conditions may require the same bus selection or register operation. OR gates combine those conditions into one physical control input.

Why operations can occur together at T1: reading memory and loading IR use the common bus, whereas incrementing PC uses PC's dedicated increment circuit. Because the two operations do not compete for the same destination hardware, both are performed during the same timing pulse.

Classifying the decoded instruction

ConditionInstruction typeNext action
D7 = 0, I = 0Direct memory-referenceAR already contains the effective address; execute the selected memory instruction.
D7 = 0, I = 1Indirect memory-referenceAt T3, use AR ← M[AR] to obtain the effective address, then execute.
D7 = 1, I = 0Register-referenceExecute the operation selected by bits IR(0-11) at T3.
D7 = 1, I = 1Input/outputExecute the I/O operation selected by bits IR(0-11) at T3.

Direct addressing means the address field itself is the effective address. Indirect addressing means the address field points to a memory word that contains the effective address. The indirect cycle is therefore required only for an indirect memory-reference instruction.

Direct and indirect addressing example

Suppose the instruction's address field is 500. With direct addressing (I = 0), the operand is found at memory location 500, so EA = 500. With indirect addressing (I = 1), location 500 does not contain the operand; it contains another address. If M[500] = 825, the effective address becomes EA = 825, and the operand is read from M[825].

Direct: EA ← IR(0-11)
Indirect at T3: AR ← M[AR], therefore EA ← M[address field]

Execution and return to fetch

After classification, the control unit activates the timing and control signals for the selected instruction. A memory-reference instruction such as AND, ADD, LDA, STA, BUN, BSA, or ISZ may continue through later timing steps. Register-reference and I/O instructions are completed at T3. When execution finishes, the control logic clears the sequence counter with SC ← 0. The next clock then generates T0, beginning the fetch cycle for the next instruction.

What happens during memory-reference execution

Every instruction ends by clearing SC. This is essential: without SC ← 0, the control unit would continue producing later timing signals instead of returning to the fetch phase.

Register-reference and input/output paths

When the opcode decoder produces D7 = 1, the address field is no longer treated as a memory address. If I = 0, one of the low-order IR bits selects a register-reference operation such as clearing or complementing AC, shifting, incrementing AC, skipping on a condition, or halting. If I = 1, the low-order bits select an input/output operation. Both classes can be identified and completed at T3 because an indirect-address memory read is not required.

Interrupt cycle

Before beginning the next normal fetch, the processor tests the interrupt flip-flop R. If R = 0, it fetches the next program instruction. If R = 1, it enters the interrupt cycle: the current PC is saved as the return address, control branches to the interrupt service program, interrupts are temporarily disabled, and the request flip-flop is cleared. After the service routine finishes, the saved address allows the interrupted program to continue.

RT0: AR ← 0, TR ← PC
RT1: M[AR] ← TR, PC ← 0
RT2: PC ← PC + 1, IEN ← 0, R ← 0, SC ← 0

These steps save the return address in memory location 0 and start the interrupt service routine at location 1. Disabling interrupts prevents a second request from disturbing the save-and-branch operation. The service routine later returns indirectly through location 0 and can enable interrupts again.

How to read the instruction-cycle flowchart

  1. Test R. A set interrupt flip-flop sends control to the interrupt cycle; otherwise normal instruction processing begins.
  2. Perform the common fetch and decode operations at T0, T1, and T2.
  3. Test D7. If it is 0, the instruction is a memory-reference instruction; use I to decide whether an indirect cycle is required.
  4. If D7 = 1, use I to choose register-reference (I = 0) or input/output (I = 1).
  5. Execute the selected operation, clear SC, test for an interrupt, and begin the next instruction cycle.

Exam-ready distinction

Instruction cycle is the complete processing of one instruction. A machine cycle is one smaller operation—such as a memory read or write—within it. A clock cycle is a single timing interval. Therefore, one instruction cycle can contain several machine operations and several clock cycles.

Overall flow: check interrupt → fetch instruction → decode opcode → identify memory-reference, register-reference, or I/O instruction → obtain an indirect effective address if required → execute → clear SC → repeat.

Computer Organization and Architecture

Computer Architecture vs Computer Organization

A clear, text-based lesson adapted from the concepts explained in the referenced video.

Watch original lesson ↗
The central difference: Computer architecture describes what a computer system makes available to the programmer. Computer organization describes how the internal hardware units are arranged and connected to implement that architecture.

Computer Architecture

Architecture is the functional specification of a computer as observed by a programmer. It defines the machine-level capabilities that software can use.

  • Instruction set and supported operations
  • Data types, word size, and data representation
  • Registers visible to programs
  • Addressing modes and memory address space
  • Input/output mechanisms

Computer Organization

Organization is the physical implementation of the architectural specification. It explains the operational units, their interconnections, and the control required to make the system work.

  • Control signals and control-unit design
  • Bus structure and internal data paths
  • Memory technology and cache arrangement
  • Arithmetic hardware and processing units
  • Interfaces between components and peripherals

Point-by-point comparison

BasisComputer ArchitectureComputer Organization
Main questionWhat does the computer do?How does the computer do it?
ViewpointProgrammer or software designerHardware designer or system engineer
VisibilityFeatures directly visible to a machine-language programmerImplementation details normally hidden from the programmer
ConcernSystem behavior, functionality, and programming modelHardware units, connections, timing, and control
Typical elementsInstructions, registers, formats, addressing modes, I/O modelBuses, control signals, cache, memory chips, ALU implementation
Design objectiveMeet the functional requirements of softwareImplement those requirements with suitable speed, cost, and technology
Effect of changeAn architectural change may require software or compiler changesAn organizational change can preserve compatibility with existing programs
Design orderThe architecture is specified firstThe organization is designed to realize that specification

How the two concepts work together

1

Specify the architecture

Decide which instructions, registers, data formats, addresses, and I/O facilities the machine must expose.

2

Choose the organization

Select the buses, control logic, memory hierarchy, processing units, and component connections that will implement it.

3

Execute software

Programs rely on the architectural contract, while the organization performs the internal operations needed to honor it.

Example: a multiplication instruction

Architecture question: Does the instruction set provide a multiplication instruction, and which registers hold its operands and result?

Organization question: Is multiplication performed by a dedicated multiplier circuit, or by repeatedly using an adder under control logic?

Two processors can therefore expose the same multiplication instruction to software while using different internal hardware. They share an architecture but have different organizations, performance, cost, or power consumption.

Example: memory

The number of address bits and the addressable memory space belong to architecture because software uses them. The type of memory chips, cache levels, bus width, and memory speed belong to organization because they implement that visible memory model.

Quick method for classifying any feature

  1. Ask whether a machine-language programmer must know the feature. If yes, it is usually architectural.
  2. Ask whether the feature explains internal circuitry, connections, or control. If yes, it is usually organizational.
  3. Ask whether it can change without requiring programs to be rewritten. If yes, it is normally an organizational implementation choice.

  1. Start with the one-bit arithmetic cell

    A full adder accepts exactly three one-bit inputs: Xi, Yi, and carry Ci. It produces a result bit Di and a next carry Ci+1. In this circuit Xi is permanently connected to Ai; the circuit changes the arithmetic operation by changing only Yi and the first carry.

    Why this matters: the hardware does not need a separate adder, subtractor, incrementer, decrementer, and transfer circuit. One full-adder path is reused for every operation.

    On the diagram: locate FA₀ and trace A₀ directly into its X₀ input.

  2. Expand the cell into a four-bit ripple-carry circuit

    Four-bit operands require four copies of the one-bit cell: FA₀, FA₁, FA₂, and FA₃. Register A supplies A₃A₂A₁A₀ in parallel. FA₀ handles the least-significant bit first; its C₁ output feeds FA₁, then C₂ feeds FA₂, and C₃ feeds FA₃.

    Parallel versus ripple: all A and selected Y bits are available simultaneously, but the final answer is not stable until each carry has travelled to the next stage. That serial carry movement is the ripple-carry delay.

    On the animation: the active glow begins at FA₀ and climbs through FA₃.

  3. Use a 4×1 MUX to prepare each Y input

    Before FAi, MUXi chooses one of four useful values: I₀ = Bi, I₁ = B̅i, I₂ = 0, or I₃ = 1. The chosen value becomes Yi. These four choices are deliberate: B supports addition, B̅ supports two’s-complement subtraction, 0 isolates A, and 1 supplies an all-ones word.

    The inverter beside each B input creates B̅i. Constant inputs 0 and 1 do not come from registers; they are fixed logic levels connected to every MUX.

    For B = 0101, the four MUXes can collectively output 0101, 1010, 0000, or 1111.

  4. Decode S₁S₀ as one word-wide selection

    The select lines are shared by all four multiplexers. Therefore S₁S₀ does not select an isolated bit: it selects the same input number at every bit position and constructs a complete word Y.

    00: Y = B. 01: Y = B̅. 10: Y = 0000. 11: Y = 1111. For example, 01 makes MUX₀ select B̅₀, MUX₁ select B̅₁, and so on.

    In the simulator: changing “Select S₁S₀” highlights the selected input wire on every MUX.

  5. Treat Cᵢₙ as the third control bit

    Cin is the initial carry C₀ applied only to FA₀. Numerically it adds either 0 or 1 to the selected four-bit operation. Logically it doubles the four MUX choices into eight microoperations, so the control word is S₁S₀Cin.

    With Y = B̅, Cin = 0 gives A + B̅ = A − B − 1, while Cin = 1 completes the two’s complement B̅ + 1 and gives A − B. With Y = 0, the same carry chooses between transfer A and increment A.

    Read the controls together: 011 means select B̅ and inject 1, therefore subtract B from A.

  6. Apply the same equation at every bit position

    Once Y is selected, the circuit always performs D = A + Y + Cin. At stage i, XOR determines the result bit: Di = Ai ⊕ Yi ⊕ Ci. The carry equation is Ci+1 = AiYi + Ci(Ai ⊕ Yi).

    The first product AiYi generates a carry when both data bits are 1. The second product propagates an incoming carry when Ai and Yi differ. OR combines those two possible carry causes.

    At each animated FA stage, compare Ai, Yi, and Ci with the displayed Di and Ci+1.

  7. Interpret D and C₄ according to the selected operation

    After FA₃ settles, D₃D₂D₁D₀ is the four-bit result and C₄ is the carry beyond the register width. For unsigned addition, C₄ indicates a fifth result bit. For two’s-complement subtraction, C₄ is normally discarded; C₄ = 1 indicates no unsigned borrow, while C₄ = 0 indicates a borrow.

    Carry is not the same as signed overflow. Signed overflow occurs when two operands with the same sign produce a result with the opposite sign; equivalently, the carry into the sign bit differs from the carry out. The simulator shows C₄, so interpret signed results separately.

    For control 111, A + 1111 + 1 = A + 10000₂: the four D bits reproduce A and C₄ becomes 1.

  8. Separate data signals from control signals

    A and B are data words: their values change with the numbers being processed. S₁, S₀, and Cin are control signals: they tell the hardware what to do with those numbers. D and C₄ are output signals. Keeping these roles separate makes the diagram easier to read.

    A follows an unselected path directly to every full adder. B follows a selectable path through the MUX bank. S₁S₀ fan out horizontally to all MUXes, while Cin enters only the rightmost full adder and then becomes an internal ripple carry.

    Do not treat S₁S₀Cin as a binary number added to A; it is an instruction code that configures the datapath.

  9. Count the hardware and understand why it is shared

    A four-bit arithmetic circuit contains four full adders, four 4×1 multiplexers, and four inverters for producing B̅. It also contains common select buses, constant-0 and constant-1 lines, and four carry connections C₀ through C₄.

    Without the MUX bank, separate combinational circuits would be required for addition, subtraction, increment, decrement, and transfer. Selecting the second operand allows the expensive full-adder chain to be reused, reducing duplicated hardware.

    General rule: an n-bit version needs n full adders, n multiplexers, and n B inverters.

  10. Derive the addition and addition-with-carry pair

    Set S₁S₀ = 00 so Y = B. The general equation becomes D = A + B + Cin. If Cin = 0, the operation is A + B. If Cin = 1, the operation is A + B + 1.

    Addition with carry is important when a processor adds words wider than its hardware. For example, a four-bit unit can add the low-order words first, then use their C₄ as Cin while adding the next four-bit words.

    Controls 000 and 001 use the same Y word; only the carry input changes.

  11. Derive subtraction from the complement identity

    For an n-bit word, the one’s complement satisfies B̅ = (2ⁿ − 1) − B. Therefore A + B̅ = A − B − 1 + 2ⁿ. Keeping only n output bits removes the 2ⁿ term and gives subtraction with borrow.

    Adding one more through Cin gives A + B̅ + 1 = A − B + 2ⁿ. Again, the n-bit D output is A − B. This is why control 011 performs ordinary subtraction without requiring a dedicated subtractor.

    If A ≥ B, C₄ is normally 1 and the D word is the non-negative difference. If A < B, C₄ is 0 and D is the n-bit two’s-complement encoding of a negative result.

    To decode a negative D word, complement D, add 1, and attach a minus sign.

  12. Derive transfer and increment by forcing Y to zero

    Set S₁S₀ = 10. Every MUX selects constant 0, so Y = 0000 and B has no effect. With Cin = 0, D = A + 0 = A; this transfers A through the arithmetic unit. With Cin = 1, D = A + 1; this increments A.

    During increment, carry propagates only through trailing 1s. For A = 0111, the input 1 changes bit 0 to 0 and carries through bits 1 and 2 until bit 3 changes from 0 to 1, producing 1000.

    Controls 100 and 101 prove that B can be completely isolated without disconnecting it physically.

  13. Derive decrement and the second transfer operation from all ones

    Set S₁S₀ = 11 so Y = 1111. An all-ones n-bit word represents 2ⁿ − 1 in unsigned form and −1 in two’s-complement form. Thus A + 1111 with Cin = 0 produces A − 1 in the lower four bits.

    When Cin = 1, Y + Cin equals 1 0000₂. The lower four added bits are zero, so D = A, while the extra 1 appears as C₄. The data result is another transfer of A, but its carry behavior differs from control 100.

    This distinction shows why both D and C₄ belong in the function table: two controls can produce the same D word while producing different carry outputs.

    For A = 0000, decrement wraps to D = 1111 with C₄ = 0.

  14. Use a repeatable method to solve any circuit question

    1. Write A and B as four-bit words. 2. Read S₁S₀ and select Y. 3. append Cin to the equation A + Y + Cin. 4. Add from bit 0 through bit 3 while recording every carry. 5. report D and C₄. 6. interpret the result according to the chosen microoperation.

    A quick verification is to calculate the same expression in decimal, reduce it modulo 16 for D, and check whether the unreduced value is at least 16 for C₄. For signed numbers, separately check the sign-bit overflow rule.

    Use this method with the controls and inputs below, then compare your manual result with the animated output.
